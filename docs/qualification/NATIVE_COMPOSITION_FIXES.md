# Native candidate: composed transport corrections

This is software work for an unqualified candidate. It adds no accepted native profile or public support claim and changes no production installation.

Independent static traces at HEAD `72f1893fca53565ddf9bfce5fdb7854f422be9c5` found two integration defects hidden behind the current qualification refusal. The fixes keep the existing Core lifecycle and transport ownership.

1. Parent delivery called the one-shot `WindowsPipeFrames.seal()` before returning; the retained process finalizer then sealed the same pipe again after actual process exit. A correct final envelope therefore could not survive that composed path. The parent now consumes ingress and marks itself finished; the existing checked owner finalizer performs the sole strict seal. Stream/HANDLE close checks, error propagation, uncertainty and repeat-finalization refusal stay intact. Seal is not made idempotent.
2. The bootstrap compared Docker mount lists positionally. Serialization order can vary without changing the mount map. It now validates unique absolute Linux destinations and boolean RW fields, then compares complete dictionaries sorted by destination. Every mount field, including unknown extensions, still participates. Closed top-level fields, identity, image, resource policy and read-only reader requirements stay enforced.

These are source findings, not observed native execution failures. The positional defect does not establish the exact failed operand of an earlier unrelated operational comparison. Previous negative evidence remains unchanged.
