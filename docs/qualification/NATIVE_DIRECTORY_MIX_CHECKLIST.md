The installed File v2 caller has an ordinary fixed startup format, version 1.2. Its immutable File v2 manifest binds one owner-approved local NTFS directory by the existing Windows grant and Full128 identity. It also binds the Linux ext4 preparation and evidence identities, contract package, implementation and artifact graph. A request supplies a run ID and prepared input paths. Candidate, frozen bytes, intent, plan, receipt and inspect keep their existing per-operation bindings.

Startup 1.2 accepts only launch configuration 1.0 and native installation manifest 1.3 for the exact bundled File v2 contract. It requires a production authority profile selected by the bundled registry and verifies all File v2 guarantee requirements before the Linux Core or Windows worker starts. The current bundled File v2 registry has no qualified profile and still refuses at this gate. The caller's diagnostic capture can precede that refusal. A launcher may return a generic unresolved diagnostic, so use the internal qualification check to distinguish an admission refusal from path handling. Historical startup 1.1 retains its original experimental admission. The same Linux Core, native channel and worker own publication. See the [fixed installation guide](NATIVE_FIXED_INSTALLATION.md).

Use a single stable manifest and evidence root for repeated File v2 runs in a directory. Changes to the registry, artifact graph or grant can change the original proof binding. Inspect historical evidence with its compatible immutable reader. Cross-contract or cross-build operations on one physical directory require a verified set of compatible historical bindings under the common Core lock. A separate evidence root for an overlapping grant does not provide continuity.
