# Shared file-publication facts: software preparation slice

Source-only draft, not an admitted native entry or final-qualification readiness.
This slice extracts two private pure functions from the existing Host adapter:
candidate construction/encoding with its unchanged 1 MiB candidate limit, and
the exact intent/plan/request/target/content correlation after trusted inspect.
The Host caller invokes them in the original positions. The original request ID
remains an explicit independent argument, not a value inferred from candidate
data. A first unexecuted draft omitted that argument; source review caught the
free name before any import, test, target operation or Git transfer. It is fixed.

Existing copy_and_hash, revalidate_frozen and Core input capture are already
shared APIs; no extra file-copy wrapper is needed. Host source timestamps,
root qualification, target probes, locks, scratch lifetime, returned evidence
before cleanup, status/error handling and explicit native refusal are retained.
No Core, authority, worker, proof, schema, registry, wire or result-format change.
No new journal, queue, provider, version owner or persistent coordination.

The evidence helper is not an input validator, authentication function or
inspection substitute. It requires facts whose original schemas and receipt
bindings have already been checked. Its pure component fixtures confer no
authority. Rehashed tampering must still fail literal request/candidate/contract,
effect-count, target, content digest/length and kind checks. Valid projection and
exact candidate bytes/boundaries are also covered. These tests are source-only
and UNEXECUTED until the exact new HEAD's remote isolated Linux CI is accepted.

The complete native high-level shell remains unfinished. Before source/scratch
I/O or channel creation, fixed startup must perform the original qualified
installation preflight once. It must reuse the same Core candidate bytes,
expected inputs and root/evidence/preparation bindings. Then the existing fresh
read-only launch must correlate receipt/intent/plan and literal payload facts.
The current closed command wire cannot carry PublishFileResult implicitly.
Unknown outcomes retain their actual launch and block retries/unsafe cleanup.
This slice does not expose a native call or remove the existing refusal.
