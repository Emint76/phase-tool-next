# Six-contract shared history: implementation checkpoint

The Source237 shared-root refusal remains preserved as its original negative.
The new implementation can bind the six existing exact experimental readers to
one installed history set. No registry, profile, authority artifact, Core,
journal, queue or version store was replaced. Ordinary NTFS admission remains
closed; this is preparation for composed qualification.

Launch configuration and history-set version `1.3` contain explicit canonical
manifest/admission pairs. Every pair keeps its own fixed bundled registry,
contract package, profile artifact and per-operation admission. The set cannot
select an arbitrary provider or discover an authority from original evidence.
Duplicate run/installation identities, malformed or omitted active members and
inconsistent wheel, composition, authorization, preparation or evidence bindings
are rejected before channel construction.

All roles must identify the same physical current/result grant and projection,
normalizing only the contract's root-binding label. Version v2 additionally
retains its explicit separate objects grant. Objects roots and projections must
be disjoint from current, and repeated Version v2 expectations must agree.

The existing Core still scans the complete original history under its existing
ext4 lock. Every original selects exactly one installed reader by run, contract,
Core and installation binding. Unknown, omitted, corrupt or unresolved originals
block dispatch; the new set never filters the scan. Saved terminal proof closes
historical execution without pretending that superseded current bytes still
match an old receipt. Fresh inspect continues to check the current named target.

Both the standard Bundle v2 recovery entrypoint and recovery operation now pass
the same validated installed history into the existing Core guard. A separate
evidence root is not a substitute for continuity on an overlapping result grant.

Component verification includes 189 Linux/ext4 checks on an initial immutable
source snapshot and 26 affected checks on the subsequent recovery-entrypoint and
interpreter-guard snapshot. Both XML results and source identities were read
through separate read-only containers. The final focused Windows suite passed
128 checks. Initial test-vector and native-harness negatives remain retained;
the documented initial history-vector failure has no separately captured local
raw log and is not presented as reconstructed raw evidence.

JobObject controls and the direct-interpreter guard. A real six-contract shared
NTFS sequence, composed C01/C02/C05, dynamic A05, G01 failure windows, B08 NTFS MIX,
the remaining original program, qualified ordinary CLI/MCP, final install and
rollback remain **NOT_VERIFIED**. Existing static A05 File v2 and B08 Linux REF
results retain their original exact scopes. FULL is excluded from this campaign.
