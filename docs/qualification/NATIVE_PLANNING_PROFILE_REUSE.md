# Reuse of Core planning and exact profile schemas

This is an unselected integration component, not a supported NTFS route. The
native bootstrap, whole-effect Broker, terminal finalizer and verified closure
remain under development. The public Host installation and qualification guard
are unchanged. A05/G01/native Core/MIX/FULL/rollback are NOT_VERIFIED.

The new profile schema1.1 has its own immutable URI. Candidate classification
requires provided_guarantees=[] and conformance=[]; production data requires
nonempty claims and matching conformance. Resolving profile data does not admit
an implementation: a future closed native installation must independently reject
candidate classification even when contract requirements are empty, authenticate
its actual composition and prove its qualified scope. A leaf source hash does
not attest the executable graph or a process.

The registry selects only schema1.0 or1.1 by the descriptor version, then uses
the exact single schema digest bound in the immutable profile package. A current
schema, descriptor-supplied URI, malformed package list or null package cannot
replace that binding. Existing POSIX schema/profile, defaultregistry and previous
native snapshot are unchanged. New profiles/snapshots must be added immutably.

The public plan builder still performs its real POSIX root checks before and
after construction, with the same logical validation and effect-building body.
The private shared factory avoids a second native plan implementation. It is
not a mutation entrypoint or a qualification exemption; append/hook branches
still contain their existing reads. A native caller must first admit exact
native grants, restrict the supported create effect and validate the resulting
logical plan. No caller-controlled bypass argument was added.

The same scope/request hash formula now accepts either resolved POSIX identities
or full native root records through a private pure projection. Host ordering and
hash domain remain unchanged. Native root records use native-root-identity-v1,
matching the existing original-intent parser; Windows volume/FileID data are
never converted into POSIX device/inode values. This function cannot authenticate
those records. Only the future closed installation may supply admitted grants.

Regression sources compare fixed pre-refactor canonical hashes, both physical
root checks, hook/capture ordering and a structural native-buffer roundtrip through
the existing parser. Synthetic identity records and native parser fixtures are
data tests; they never enter a native executor or qualify NTFS. Missing security
tests remain missing regardless of these component results.
