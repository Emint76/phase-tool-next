# Static original-evidence read binding

This internal, unselected component joins the existing Linux/ext4 four-object
reader and the existing original-intent parser. It is not a native Installation,
authority provider, callable service, trusted bootstrap or qualification result.
The normal host installation, root guards, registry, contracts, schemas and
default selectors remain unchanged. There is no new journal, queue, PENDING
state, receipt owner or document version model.

The reason for this seam is independent selection of static expectations. Reading
expected roots, contract or provider from the same original intent would let a
request supply both the observed and expected values. Core already owns the
operation lifecycle; its recorded intent cannot itself establish the deployment
configuration selected by a trusted startup. This binding supplies only that
static correlation and reuses the existing lifecycle and semantic validators.

The installation module accepts bounded immutable canonical manifest bytes and
an independently supplied expected raw SHA. This only checks correlation with
that expected value; a future authenticated startup must establish its provenance
before selecting this component. It must separately establish the checked loaded
executable/dependency graph. Declared hashes and matching buffers do not prove
loaded code, Docker identity, native root identity, current invocation or G01.

The private manifest format `native_read_installation_version: "1.0"` is closed.
It contains the Core and exact allowed contract bindings, registry snapshot,
authority profile/provider and mechanism bindings, installation ID, composition
and artifact graph digest, Linux evidence root and ext4 identity, and full native
root grants. It contains neither its own descriptor digest nor an intent. The
expected raw SHA supplies the installation descriptor digest, avoiding a cycle.
The artifact graph must exclude the manifest and original intent.

Static field shapes reuse fragments from the contract-package-bound intent 1.2
schema. The old contract generation cannot provide this binding. Existing native
grant validation and the reader's extracted pure evidence-identity validation are
reused. No descriptor or published schema is changed. Profile/provider fields are
structural claims here; they do not register or qualify an implementation.

The read method takes only run ID and original intent profile digest. Paths and
static expectations come from the immutable manifest. Registry drift is rejected
before reading. The existing reader qualifies the actual Linux/ext4 evidence
root, checks its device/inode and reads only the original intent, effect plan,
pre-validator results and frozen blob with its existing bounds. It does not
construct an EvidenceStore or reconstruct missing evidence. Some static intent
comparison happens after those bounded reads in the owned evidence namespace;
this is not an additional isolation guarantee against hostile namespace changes.

The original nonce and effect-plan digest remain per-operation values. The
binding supplies their original values to the unchanged complete parser, which
checks the same four buffers and their schema, candidate, hashes, plan,
preconditions, content, roots and idempotency linkage. A static mismatch cannot
return the parsed task. Nonce correlation grants neither freshness nor GO/retry.
One static manifest can correlate multiple synthetic operation snapshots without
adding per-operation deployment state.

The initial subset remains single frozen-input `file_create.v1`, existing parents,
at most 1 MiB. The manifest does not extend this subset to update, bundles or v2
large inputs. Existing Core remains the sole owner of intent, idempotency,
receipts, inspect and recovery. Root-wide unresolved checks, operational locks,
current observations, authenticated transport/bootstrap, bounded worker lifetime
and admitted dispatch remain necessary integration work.

At source preparation, new tests are not executed. They cover pure refusal and
actual qualified Linux/ext4 synthetic read-only fixtures, including one unchanged
manifest across nonce/plan changes, static mismatches and saved false
preconditions. No successful qualification is mocked and no native worker runs.
Execution results must be bound to the later exact CI HEAD and build. A Linux
test or synthetic intent is not Windows qualification. A05/G01, native Core
create/update/bundle, MIX/FULL and native runtime rollback remain NOT_VERIFIED;
this component does not enable a supported NTFS route or release.
