# Shared original semantic checks: internal prerequisite

This source checkpoint factors existing original validation inside intent.py.
It adds no installed role, file2 selection, protocol, descriptor, registry,
profile, authority, Core lifecycle, journal, queue or document-version store.
The production qualification guard is unchanged. Native A05/G01/G02, positive
CLI/MCP, full REF/MIX/FULL family, native rollback and release remain
NOT_VERIFIED; FULL stays disabled. New tests are UNEXECUTED at first retention.

## Existing full-byte paths remain mandatory

The four public executing/planned wrappers and their signatures stay unchanged.
Their existing private full parser actively reuses a shared prefix and suffix
in the historical order:

1. exact intent/schema/registry/core/native/implementation/plan/candidate/effect/
   frozen declaration checks;
2. actual immutable blob type and fixed1MiB/file1 or16MiB/version1 cap, actual
   full SHA, declared frozen/effect/content-source/digest/length correspondence;
3. installed roots, native grant, root identity/idempotency, saved preconditions
   and exact worker context;
4. the same five-field ParsedNativeFileCreate or ParsedNativeVersion1 tuple,
   retaining the actual original bytes. Planned wrappers still return None.

The full parser never calls the controls-only seam. No skip-content switch,
caller-selected bound, FD, iterator or callback replaces actual verification.
The existing reader still reads and hashes its full immutable payload with
fresh root checks before handoff. This refactor creates no new file access.

Source comparison confirms the four public wrapper ASTs are unchanged and the
prefix/payload predicate/suffix checks were extracted in order. That is a
source observation, not a claim that the whole private parser AST is unchanged
or that execution has passed before CI. Tests explicitly cover the historical
prefix-before-payload and payload-before-suffix multiple-fault priority.

## A separate declared-data projection

_parse_original_controls joins those same complete prefix/suffix semantics with
declared-content consistency and returns a DISTINCT frozen private projection:
canonical context/grant/effect bytes, timestamp, input binding, declared digest
and length. It has no content_bytes field and is not a historical full handoff.
Metadata are detached immutable bytes/scalars; no source path or FD authority,
installation authentication, actual payload check, filesystem fact, worker exit
or GO permission is conveyed by matching values.

This private API rejects declared lengths outside its historical fixed bounds
and malformed declared digests. Its declared-bound error is specific to this
different API; error equivalence with an actual-byte parser is not asserted.
A consistent declaration can describe an incorrect actual length, or remain
available after a frozen blob disappears. Only the full byte reader/parser or
a later separately bound verified snapshot can establish actual content.

The first unexecuted extraction draft omitted one candidate local in the shared
suffix. Root static inspection corrected that exact binding before any candidate
execution; the rejected draft remains in the private source lineage. Two
separate preliminary reviewers then found no concrete module blocker. Their
same-host source review is neither external certification nor final acceptance.

## Verification scope and future integration

New controls compare exact tuples/projections against fixture-derived literal
context, grant, effect and hash expectations for both contracts and modes;
test distinct frozen metadata, mandatory actual-byte type/hash/caps, rehashed
suffix refusals, prefix/payload/suffix fault priority and absence of source,
snapshot or NativeIO access from pure validation. A real qualified ext4 reader
fixture removes only its owned synthetic blob: raw controls and declared-data
projection remain readable while the full reader must fail without writes.
The existing complete original/reader/guard test suites remain unchanged.
Fixtures contain explicit synthetic native claims; ordinary Host plans or pure
data matching never authenticate a Windows installation or qualify NTFS.

A future fixed file2 composition still needs contract-specific selection,
complete installation coverage and correlation to actual Core FrozenInput,
Core-owned verified anonymous snapshot, original ALLRO process exit, one gated
two-pass exchange, native effect/observation/proof and real finalization. The
new projection does not claim those properties and keeps the1MiB/16MiB role
caps. Full2GiB/native/backpressure/deadline/RSS measurements are separate.
No old descriptor, historic receipt format or production route is changed.
