# Delivery scope after the explicit 27 October instruction

This addendum records a new authorized delivery scope. It does not rewrite the
original qualification program, historical descriptors, failed tests or results.
The authorization is retained privately with SHA-256
`6d3646ce58d6045fae41d1b22791c4f05d6cb177c343883fad86cd6ae0b0a40b`.

Phase must trace operations actually performed through it: exact request,
candidate and frozen bytes, selected target and prior state, implementation,
physical outcome, preserved versions, receipt and independent verification.
It need not enforce a globally exclusive write channel or resist an arbitrary
privileged replacement of the entire runtime. Out-of-Phase changes are detected
as discrepancies; their cause and author must not be invented.

## Bounded first experiment

Only a separate fixed experimental startup may select the new file1 experimental
registry. The ordinary guard and immutable old descriptors remain strict.
The experiment uses the existing Core, lock, intent, frozen input, Windows worker,
receipt and independent RO inspector. It creates no new journal, queue, version
store or Core. A closed context binds one run, candidate/payload, target grant,
private ext4 identities, build and authorization. Its canonical bytes are an
EvidenceStore attachment; their SHA is also part of the installation identity.
Missing or inconsistent context/evidence must prohibit dispatch or verification.

An experimental descriptor has empty provided_guarantees/conformance. Structural
assessment of the unchanged contract obligations does not certify coverage.
Functional success of one operation is distinct from qualification. Ordinary CLI
and MCP cannot activate the experiment from a request or a profile identifier.
First execution is one small synthetic file in a fresh physically disjoint owned
NTFS domain; a fresh RO invocation uses the same admission and new launch nonces.
Inspect unknown outcomes before any new controlled trial; never retry/rekey blindly.

## Required family and completion

All six contracts remain required: file_create.v1/v2, publish_new_version.v1/v2,
bundle_create.v1/v2. The initial file1 admission does not admit the other five;
subsequent closed extensions need their own source review and real route checks.
Unchanged size, versioning and recovery semantics remain binding. Installation,
CLI/MCP, evidence compatibility, native rollback and repository checks remain
release gates. No support or release is accepted by this document.

No exact ISO standard/edition/clause has been established in available approved
sources. This is an open normative clarification, not an engineering stop.
ALCOA+/GAMP guidance in GOAL.md is not certification. Caller identity and system
timestamps are recorded for what they are; they are not verified authorship,
electronic signatures or approvals.
