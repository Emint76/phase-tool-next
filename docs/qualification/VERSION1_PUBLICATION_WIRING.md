# Version1 fixed preparation and raw MCP wiring

Software candidate only. Native NTFS support, A05 and G01 remain NOT_VERIFIED.
The qualification guard is unchanged and refuses this unqualified installation.
No positive native preparation/CLI/MCP operation is claimed by these components.

The closed phase_execute_version1_publication tool accepts only run_id,
source_locator, target_locator, request_id, expected_current_digest and optional
expected_digest. A fixed installation supplies every root, registry and binding.
A separate discriminator selects the existing seven-field version1 request and
original-query1.2; file1 and historical query generations retain their grammar.

The candidate builder produces the existing five-field publish_new_version.v1
candidate. The existing contract owns deterministic archives, state validation,
version transitions and receipts. The helper rejects target/archive collision
without reading the Linux projection of the Windows target.

Preparation repeats the existing file1 admission/type/namespace pattern, then
uses the existing copy_and_hash/revalidate_frozen path in the admitted ext4
preparation root. Candidate bytes and payload hash/length are passed to the SAME
PhaseApplication/Core. The existing16MiB version1 payload bound is unchanged;
file1 remains1MiB. Scratch remains available after unknown outcomes. No target
write, archival copy-out, alternate publisher or cleanup owner is added.

A separate Core branch catches only early preparation errors. The actual
app.run remains outside that catch. Core owns capture, intent, common/per-key
locks, archive/publish, validators, receipt and existing recovery semantics.
The existing MCP call owner/gate retains unknown launches and refuses later
calls. Raw execution returns unchanged CommandResult, not PublishFileResult,
automatic inspect, a verified highlevel result or retry authorization.

This slice adds no durable component: no journal, queue, PENDING/FINALIZED state,
version store, receipt schema, new authority profile or registry trust. The pure
candidate builder is needed to correlate exact caller literals; the prepared
input adapter is needed to enter existing Core from the fixed input namespace;
the raw MCP method is only the transport adapter. Existing mechanisms own every
other guarantee. File2, bundles, version2 and FULL are not enabled.

Known-run inspection remains the existing independent read-only route. A
version1 caller-literal/receipt-pinned inspection grammar and highlevel version
correlator are unfinished; file1 inspection literals must not be reused for
version1. Existing recover_publication excludes publish_new_version.v1; no new
automatic recovery is supplied here.

New focused tests are UNEXECUTED until exact-HEAD CI artifacts are retained and
checked. They cover closed request/schema, query1.2 mapping, exact candidate,
archive collision, real unmocked native guard, gate/unknown-delivery retention,
real SDK invalid-startup refusal and qualified Host Core version/archive/fresh
inspection under explicit synthetic process boundaries. They do not establish
accepted native preparation, G01, Windows byte persistence or safety admission.

The existing request fingerprint includes frozen_at. A deterministic default
clock negative regression is proposed: unchanged candidate/payload/root/key at
T1 after success atT0 must conflict without modifying current/archive/prior
receipt. An explicit T0 control tests exact-fingerprint reuse only; it is not a
runtime retry strategy. No timestamp/key substitution, fingerprint change or
historical binding edit is introduced. After unknown delivery inspect the known
run; do not rotate identifiers or resubmit to mask a conflict.
